# Minori Runtime Progress

This document records evidence and implementation checkpoints for the independent Rust Minori runtime. Machine-local game paths, extracted assets, screenshots, saves, and IDA databases are excluded from the repository.

## Stage 0: Original Runtime Baseline

Status: investigated.

- The original is a proprietary 32-bit C++ Minori runtime with `ScriptEngine`, `ScriptPool`, scene classes, and 49 RTTI-visible `Command*` classes.
- `SceneGame::activate` at `0x47B360` creates the script engine and opens `test.sc` through `0x4502A0`.
- `0x4502A0` creates the command/parser object at `0x4630D0`, loads the script through `0x465C70`, then installs it into the active engine.
- `SceneGame` calls the large active engine update routine at `0x450F50` from `0x47B570`.
- The original title, NEW GAME route, SceneGame black handoff, and persistent global store are implemented.

## Stage 1: Rust VFS And Script Corpus

Status: verified.

- The Rust VFS mounts the original PAZ archives and decodes version-2 index/data encryption, generated-key RC4, and zlib entries.
- The real `scr.paz` contains 49 scripts. All 49 were bulk-extracted to a temporary directory for whole-corpus analysis; no extracted game data is stored in the repository.
- The full corpus uses 25 command names. Highest-frequency commands are `.char` (17,483), `.message` (16,717), `.stage` (7,922), and `.transition` (7,890).
- Script flow contains 47 `.chain` commands plus a small number of `.if`, `.goto`, and `.label` commands. `test.sc` begins with `.chain A00_01.sc`.
- The product parser successfully validates all 49 extracted scripts in one run: 51,968 statements and 51,910 commands, with no unknown command names or parse failures.
- `mov.paz` uses its separate verified scheme: the decrypted index contains a 256-byte movie key after the entry count; each entry derives a 256-byte RC4 key by XORing that table with its Shift-JIS entry key, generates at most 64KiB of keystream, then repeats that block across the AVI. The real archive exposes `sppl_01_op.avi` (107,763,780 bytes) and `sppl_ed.avi`; decoding the OP produces a valid `RIFF ... AVI LIST` header.

## Stage 3: Complete Command Registry And VM Core

Status: investigated; Rust scheduler prototype.

- IDA confirms that `0x4630D0` registers the original command classes. Each command vtable uses slot `+0x04` for argument parsing and `+0x08` for execution.
- Rust now has a complete registry for all 25 commands used by the real script corpus. Every registry entry records the original parser and execute addresses.
- Confirmed examples:
  - `.char`: parse `0x446D60`, execute `0x447480`
  - `.stage`: parse `0x44E020`, execute `0x44E3B0`
  - `.message`: parse `0x449770`, execute `0x449880`
  - `.chain`: parse `0x4480B0`, execute `0x446AD0`
  - `.if`: parse `0x448F90`, execute `0x449010`
  - `.transition`: parse `0x44E930`, execute `0x44EA10`
- `.set` and `.setGlobal` are complete from shared parser `0x44CB80` and evaluator `0x44CC40`. Both accept direct `NAME = VALUE` and computed `NAME = LEFT OP RIGHT`; values resolve through the appropriate local/global container and all original operators `| & + - * / %` are implemented. Division/modulo by zero is a fatal diagnostic instead of a Rust panic.
- `.transition` VM dispatch is implemented without guessed rendering. All 7,890 corpus occurrences have exactly three arguments. The original parser reads integer type, mask string, and integer duration; execute writes the pending scene transition configuration and returns true. Rust emits and retains the same typed configuration for the following `.stage` command. Every original type 0..18 is implemented as described below; out-of-range types take the original immediate-swap default branch.
- `.stage` argument parsing is implemented as a typed request, not rendering. The corpus contains 7,864 four-argument, 12 six-argument, and 46 eight-argument forms. IDA `0x44E020` confirms the base/composite spec, optional base x/y, main image x/y, and up to ten extra `name value` pairs where value may be `first,second`; execute `0x44E3B0` forwards that structure to `0x4549A0`. Rust covers the standard and extended forms in tests and retains the request for the future scene service.
- Stage composition is restored for every corpus shape. IDA `0x457420` loads the main image through `0x430220`, then gives `base_spec` to `0x42E8C0`; its fixed grammar is `screen:BG,ST,FG`, with `*` denoting an empty slot, matching the original `!screen_BGFilename`, `!screen_STFilename`, and `!screen_FGFilename` fields. Rust composites main image, optional extra layers, BG/ST/FG, and the screen effect using source alpha, then copies the viewport. `0x42F990` clamps copied width and height to source bounds instead of rejecting a partial viewport: 1380x820 resources at `50,50` produce a centered full frame, while a 1280x720 source at `50,50` copies the available 1230x670 region over the cleared canvas.
- Type 0 transition execution is implemented as a blocking scene state. IDA `0x436630` and `0x435130` establish `progress = duration * elapsed_10ms / 10`, 0..255 old/new linear blending, completion only after progress exceeds 255, and no next command on the completion update. Soft-mask type 1 follows `0x4353F0`: for progress below 512, every pixel uses `alpha = clamp(inverted_mask + progress - 256, 0, 255)` and the exact signed `(old + ((new-old)*alpha >> 8))` channel formula; a missing mask or progress at least 512 installs the new frame. Zoom type 2 follows `0x4358A0`: its 200-entry scale table is `1 + index^2 * 0.00249993687`; progress 0..199 center-zooms old with the forward table, progress 200..399 center-zooms new with index `399-progress`, and every frame floor-averages that temporary surface into the retained output. `0x419010 -> 0x418E70` uses centered integer crop dimensions and Bresenham nearest-neighbor expansion, not filtering. Tile types 3..13 follow `0x4359E0`: the frame is divided into 40x40 cells, each signed delay advances by the global progress delta, and a cell grows from its upper-left in 4px steps whenever `value/(columns*rows)` crosses 0..10. Types 3..11 initialize simultaneous, forward/reverse row and column, forward/reverse diagonal, outside-in radial, and center-out radial delay fields. Type 12 assigns `-(rand()%total_delay)` per cell; type 13 performs the original 32-step in-place random column permutation before applying the row stride. Their `rand()` calls now share one SceneSystem MSVC sequence with screen shake, matching the original process-global default seed 1. Rectangular types 14..17 are restored from `0x436290/0x436320/0x436430/0x4364B0`: type 14 copies the new frame through `(0,0,progress,progress*height/width)`, type 15 keeps the same new upper-left/old lower-right split and clears the two other rectangles to opaque black, type 16 reveals from the top, and type 17 reveals from the left. Their completion threshold is the corresponding image width or height. Mask type 18 follows `0x435770`: `0x45B390 -> 0x415C80` loads an 8-bit grayscale mask and bitwise-inverts every byte, then each update copies new-frame pixels whose mask value lies inclusively between previous and current progress. A missing mask takes the original immediate installation path; progress above 255 is processed once before completion on the next update. The `0x436630` dispatcher has cases only for 0..18; every value outside that table immediately installs the new surface through `0x415750`. The corpus's sole type 22 therefore correctly swaps immediately.
- `.char` parsing is typed for all 12 original modes recovered from `0x446D60`: `load`, `pos`, `size`, `order`, `order2`, `blendrate`, `visible`, `clear`, `move`/`moveofs`/`allmove`, `freeze`, `seq`, and `keep`. The constructor at `0x446BD0` supplies the encoded defaults; hidden parser tokens at `0x4EBC80/84/88` are `add`, `sub`, and `on`.
- The complete game corpus uses only six `.char` modes: 7,249 `load`, 7,247 `pos`, 2,415 `keep`, 220 `blendrate`, 176 `seq`, and 176 `order2`. Those paths execute through one abs(id) character object with current/next scene membership, matching `CCharLayer`: negative load targets the next scene, positive commands still address the same object, `+220 keep` marks it for the next stage, and stage swap promotes next membership and clears the keep flag. Timed sequence names replace the four-digit suffix and advance at the parser-supplied frame rate. Dormant `size` is also restored from `0x43DB80 -> CCharLayer::vtable+52 -> 0x40FB00/0x4193D0`: both loaded buffers are resized using `0x419360`'s `floor(destination_index * source_size / destination_size)` nearest-neighbor map, and later sequence frames retain that size. Dormant movement is restored from `0x43DD60/0x43DC80` and CCharLayer update `0x40FF00`: duration is measured in the global clock's 10ms units, x/y independently use linear, `t*t`, or `2*t-t*t` easing, integer conversion truncates toward zero, and optional blend rate interpolates linearly. A negative move id targets all layers; `allmove` is the original shorthand for negative id plus offset and blocking flags. Blocking moves use an explicit VM wait until all active layers finish. Manager lookups for mutation commands are nullable in `0x43D590/0x43D9E0`; a missing target is an intentional successful no-op. This is exercised by the original A03 `.char order2 1000 100` with no id 1000 loaded, and the real harness now continues beyond it.
- Dormant `.char` secondary/tertiary load fields are restored. `0x40F300` loads the primary surface at object offset `+0x150`, optionally loads the secondary surface at `+0x2C0`, and stores all three resource names through vtable slot `+248`; the tertiary field is metadata and is not decoded by this load path. `0x4107B0` submits the primary surface first and the secondary surface second when byte `+0x25E` is set, so Rust preserves that source-over order with the character layer's common position/blend and resizes both loaded surfaces together. Non-timed sequence is restored from `0x410E30`: it clears the active timed-sequence flag and retains the currently loaded frame; only a timed request enables the `1000/rate` frame clock. Freeze is restored from `0x43EBF0`: eligible loaded layers are composited into the current scene canvas with their existing order/blend, then `0x43CE00(0)` removes every character layer.
- `.message` parsing preserves the original four fields `id, voice, speaker, text`. IDA `0x449770` requires at least four parser tokens, stores token 0 as the integer id, tokens 1 and 2 independently, and joins token 3 onward with spaces. Consecutive spaces therefore encode empty voice/speaker fields and may not be collapsed by the generic argument splitter.
- `.pragma` is complete from `0x44AFD0/0x44B020`: `skip_enable/disable`, `enable_control/disable_control`, `clear_global_variables`, `clear_local_variables`, and `monologue` are implemented. Monologue scans forward for a message beginning with the 13-byte `monologue_end` marker and moves the active command index there. The 49-script corpus uses 52 enable and 5 disable commands.
- `.panel` parsing and scene execution cover every corpus form. IDA `0x44A450` reads mode, an optional integer defaulting to `-1`, and an optional image name; the corpus uses 695 one-argument `0/1` forms and four `.panel 1 * msgPanel_girl.png` forms where `*` preserves the `-1` default. Execute `0x44A560 -> 0x455090` starts engine state 17. `MessagePanel::start` at `0x442DC0` substitutes speed 16 when the argument is non-positive, mode 1 defaults to `msgPanel.png`, and places it at `y = 720 - image_height + 64`. Scheduler state 17 calls vtable `+0x68 -> 0x4459B0`; alpha is `min(elapsed_10ms * speed, 255)` and completion is `elapsed_10ms >= 256 / speed`. State 18 finalizes through `0x444790` without executing another command that update. Rust implements the same open/close/custom-image crossfade and VM resume boundary.
- Panel composition now survives every scene-target rebuild. Panel state was retained, but `.stage` and character/voice refresh paths previously replaced a pending transition's `new_rgba` with background+characters only, leaving text visible over a missing light panel. Stage targets and all character refreshes now apply the active panel or its opening/closing transition before installation. A focused regression holds an active panel through a scene transition target rebuild, and the product message-360 probe retains the lower panel while voice-driven mouth frames update.
- Closing a panel now clears the host text layer at the original transition-completion boundary. IDA `0x444790` destroys the old current objects and promotes the empty next objects when mode 0 completes; Rust previously completed only the scene panel and left Godot's `MinoriMessageText`/speaker labels alive. A product probe reached A00 message 250 with the text node present, executed `.panel 0`, and confirmed the node was released after the close completed.

- Supipara's eight title-specific PAZ Blowfish key pairs and archive mount order now live in `SUPIPARA_PROFILE.archive_keys`. The VFS owns only generic index/data/movie decoding and accepts a selected profile; standalone tools detect a profile from the archive directory. Save-slot host labels likewise receive profile-derived logical rectangles, so no Supipara grid coordinates remain in `AetherRuntimePlayer`. The full save/load product chain still passes after both migrations.

- `.chain` persistence failure is non-fatal in the original: `0x446B06` ignores `Variable::save`'s return value and always writes `NEXT`. Secure mode is enabled by WinMain writing `word_50CF3C = 0x0101` at `0x477191`. Rust mirrors `0x467C80/0x467D50 -> 0x46BF90 -> 0x46B970`: globals are sorted by Shift-JIS name and serialized as `name\tdecimal\n` plus NUL, compressed as a level-6 zlib stream, prefixed with the little-endian plaintext length, zero-padded to an 8-byte boundary, and encrypted blockwise with the original little-endian-DWORD Blowfish variant and key `minori`. Loading reverses `0x467FB0 -> 0x46BDD0 -> 0x46C010`, validates the plaintext length, and injects the globals before `test.sc` starts. The platform ABI writable directory replaces the original executable directory as the `system.dat` location so installed game assets remain read-only; the byte format is unchanged. Save failure leaves `persistence_pending=true` and records a diagnostic without blocking `.chain`.
- `.chain` is now modeled as an engine-boundary transition. `CommandChain::execute` at `0x446AD0` finalizes the current script, persists globals through `0x467760`, writes the target to `NEXT`, and returns false. The `ScriptEngine` update tail reads `NEXT` at `0x45358D`, loads it through `0x465FA0 -> 0x465C70`, installs it through `0x450500`, and returns; the new script executes on the next update.
- The active scheduler at `0x4533C9-0x453505` increments one command index, fetches one command through `0x465B40`, calls its vtable `+0x08` execute method once at `0x4534B9`, and then returns or processes `NEXT`. Rust therefore executes one parsed command per provider tick; the former arbitrary 512-instruction budget loop was removed.
- `CommandBase` accessors at `0x4468B0-0x446910` confirm the per-command skip/control flags and source/target indices consulted by the scheduler. Empty source lines are omitted; comment and label command objects consume an update like the original.
- Focused tests prove one command per update and the deferred entry transition from `test.sc`: statements after `.chain A00_01.sc` are not executed, persistence is requested, and `A00_01.sc` starts on the following update.
- Unknown commands and registered-but-unimplemented commands now stop with an explicit diagnostic containing the original parser/execute addresses. They are no longer silently emitted as scene events.
- The former script-driven retained renderer and guessed `.char` behavior were deleted. No visual command is considered implemented merely because a selected `A00_01.sc` screenshot could be produced.
